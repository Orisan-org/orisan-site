Both lines above are the digests PyPI PUBLISHES. The wheel digest was additionally
re-derived inside the recording by streaming the bytes PyPI actually serves through
`shasum -a 256` (run.txt, step 2). Published and re-derived agree.

Caveat on what this does and does not bind. uv unpacks wheels into its cache
(archive-v0) and does not retain the .whl, so there is no cached file to hash. The
digest therefore binds the artifact PyPI serves for orisan-mcpscan 0.1.1, and step 4
shows uvx resolved 0.1.1 from the environment step 3 built. It is not a hash taken
from uv's own installed bytes. To bind that directly, install with
`uv pip install --require-hashes` against this digest and let uv do the check.
